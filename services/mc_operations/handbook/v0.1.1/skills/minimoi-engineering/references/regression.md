# Regression and usefulness reporting

Version: 0.1.1

Maintain versioned, re-executable suites with stable case IDs and dated revisions.
Questions may change and new ones may be added. Record which exact suite/case
revision each run used; changing a question or expected answer is not a comparable
repeat of the old case. Code and sanitized suite definitions may live in GitHub;
private prompts, gold answers, source text and raw outputs remain private.

Retain dated run IDs, environment and code/model versions where available, source
and index editions, settings, permissions, inputs, output/evidence hashes, results
and errors. Preserve original runs. Assessments and corrections are separate linked
records; do not rewrite old outcomes to make a trend look better.

Separate automated execution, retrieval/citation integrity, semantic support,
chronology, usefulness and owner acceptance. An exact citation range proves a
source location, not that it supports the claim. Zero errors, a large pass count or
a successful import does not mean a useful answer. Unsupported temporal questions,
missing dates, inaccessible sources and unreviewed gold answers remain explicit.

For drift/improvement reports, compare like-for-like cases or name confounders:
changed questions, model, data, time range, index or permissions. Include dates,
regressions, improvements supported by evidence and gaps. Robert can request these
reports on demand; no recurring weekly or monthly schedule is activated here.

Include real user journeys for Board follow-through, service access, persistence
and voice. Test shared capabilities across their actual consumers. Voice acceptance
includes natural conversation, separate insertion-only Dictate, provider selection
and optional transcript after End. Synthetic speech/transport tests do not replace
Robert's phone/microphone experience.
