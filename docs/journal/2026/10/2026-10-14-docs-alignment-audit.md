# GitHub documentation alignment audit

## Verdict

The public repository describes mini-moi as of mid-August 2026. Since then the platform has shipped the quiet Guild alpha to production, shared full-tool CoS/MC agent access, voice with a daily allowance, a memory shelf with roughly a thousand records, a Workshop journal, Rooms and Records, Planning Studio, Prototype Lab with a public IoT Connect beta, and has reorganized around CoS-everywhere, a Workshop per host, and a platform-wide Vault. None of that is in README, ARCHITECTURE, OPERATIONS or ROADMAP. The documents are not wrong about what they describe; they are two months and one reorganization behind, and in four places they now state the opposite of what is live. The fix is one refresh of the root four plus AGENTS.md before the 1.2 release, a release record with it, and an archive pass after, each a docs-only PR.

## 1. What is true today that the documents do not say

Each item below is in the repository's own records (handoffs, PRs, specs) or in the October decision documents, and is absent from the root four.

**Shipped**
- Guild quiet alpha in production (portal image `8f7b06e`, Guild NEXT/PRODUCTION/PRIMARY on, CHAT set to CoS). ROADMAP's release record ends in August.
- Shared CoS/MC agent with full tools and execution in production (PR 301, 13 October). ARCHITECTURE and ROADMAP still say CoS Agent A has web search only and "cannot alter the platform."
- Shared voice with a $20 Chicago-day allowance in production (PR 302, 13 October). README's "realtime voice" is the August CoS voice only.
- Nine application containers on immutable tags at `2acbe111`; per-service resource ceilings on dev; original PostgreSQL image retained. OPERATIONS' topology diagram is the five-plus-three August layout.
- Memory shelf (the Vault's implementation): capture of Claude Code and Codex sessions on a 04:00 job, manual Claude.ai and Grok imports, immutable editions, a coverage matrix, T1 portable tools reviewed (R1–R16), a real-data restore drill in an isolated container, Ask with citations in review. Not mentioned anywhere.
- Workshop journal v2, workflow, check-in, replica reader; Rooms/Records (SQLite, workers, connector); Planning Studio with two public initiatives; Prototype Lab with four projects and the IoT Connect public beta of 4 September. Prototype Lab appears in the Guild navigation and nowhere in the documents.

**Decided**
- The 9 October reorganization: CoS is the one assistant everywhere in production with per-domain scope; the CoS domain is the personal space; Guild is the build space; each Workshop has its own MC on its host; there is no separate Journeyman and no production MC above the Workshops. ROADMAP's Direction and ARCHITECTURE's CoS/Guild section describe the opposite: a planned Master Craftsman inside Guild as a separately governed agent, with CoS bounded to consult interfaces.
- Three stores, three questions: GitHub for what the work is, the journal for who is doing it, the Vault for why.
- The Vault covers every domain from day one, outlives mini-moi, and has an owner-held custody path. The rule "the capability is public, the instance is private."
- A local server remains in the plan; Linux, Q1 or Q2 2027 as the likely window; the Vault pass as the first local workload. ROADMAP's Planned item ("rented cloud first, then owned hardware; the Mac Mini could return") is the August version of the same thought.
- MiniMoi 1.2 beta as the umbrella release, delivered in bounded production chunks from the quiet alpha baseline; the seven-green-days gate from v0.7 explicitly reconciled by the owner for that path.
- Frictionless rules: chat first, one place for each thing, post-its not dashboards, Build Log from GitHub.
- Models configurable and swappable everywhere (binding, 8 October). README already says this; ARCHITECTURE's follow-up item 5 (LLM_REGISTRY correction) is still open.

## 3. Contradictions to resolve, not just update

1. **Master Craftsman and CoS.** The documents say MC is a planned agent inside Guild, separately governed, with CoS bounded. The decision is CoS everywhere with scope, MC per Workshop, no production MC above workshops, one shared agent for now. Every mention in README, ARCHITECTURE, ROADMAP changes.
2. **CoS authority.** "Cannot alter the platform," "browser, filesystem, runtime, messaging denied" versus full tools and execution live since 13 October as a single-user experiment to be scaled back by use. The documents should state the experiment and its intent, not the August bound.
3. **Single editor.** AGENTS.md's one-agent rule versus the 13 October contention exception. State the current rule: disjoint worktrees with actual ACK, one heavy job.
4. **Local models.** ROADMAP's "rented cloud first" versus the October snapshot's "Vault pass first on owned hardware, local server when justified." Replace the Planned item with a pointer to the research topic.
5. **"No new domains except French."** Still the rule for domains; Prototype Lab and Planning Studio are Guild capabilities, not domains, and the documents should say so to keep the rule true.
6. **Release gates.** v0.7's seven green staging days versus the owner's incremental-chunk delivery from the quiet alpha. Record the owner's disposition in ROADMAP's principles ("Production verification is required" stands; the soak gate is replaced by per-chunk verification until 1.2 closeout).

## 6. Decisions (Robert, 14 October 2026)

1. **Three-pass plan: approved.** Pass A before the 1.2 release.
2. **CHANGELOG: retired.** Too much activity already for another document to keep. It gets a dated banner pointing at `docs/releases/` and the ROADMAP release record, and an archive entry. Nothing is backfilled.
3. **`_NewDomains/`: goes away entirely.** The folder stayed because of the code dependency (§2); that dependency is what gets retired, by moving the research-intelligence package into the Curator domain and remapping the data volume. New domains are not what Planning Studio is for: new research and ideation happen in Planning Studio; a domain is a product decision made from there.
4. **LLM_REGISTRY: kept and brought up to date, in two parts.** Part one is the current rotation, generated from the gateway configuration so it cannot drift. Part two is a hand-kept record of models used before or under consideration but not in rotation — what they were tried for, why they left or have not entered. The STALE banner comes off when both parts exist.
5. **Planning Studio: public capability, private instance.** The studio has almost no code of its own (48 Markdown, 10 JSON; the portal reads it through `guild_ui/references.py` and `workshop/`), so the charter, record lifecycle, templates, schemas, patterns and registry stay public as the capability. The initiative records are the instance. The two initiatives in the repo today (central personal repository, Curator open subject) are about mini-moi itself and can stand as the public example data; personal initiatives from here on go behind the instance line. Prototype Lab holds the code side. How the private line is enforced (ignored subtree, separate private repo, or a data directory outside the repo) is decided with the vision document's §9, not by this audit.
6. **Who executes.** Direction of travel: the Master Craftsman becomes the single entry point for everything engineering and divides work among Claude Code, Codex, Grok or whoever is next; the Chief of Staff becomes the planning partner on the same pattern. Robert always keeps the right to go directly to any agent — to Claude Code for a deploy, a fix or an investigation. Nothing is to be overfitted yet; the team is still learning by doing and using. For this audit: Pass A is one docs-only PR executed by Claude Code from this document, Codex reviews, Robert approves; the `_NewDomains` move is a Codex chunk; Claude Chat stays with Robert on the README and ROADMAP Direction wording and the release-note narrative; the Pass C standing checks go to the Master Craftsman once it exists as the entry point.
