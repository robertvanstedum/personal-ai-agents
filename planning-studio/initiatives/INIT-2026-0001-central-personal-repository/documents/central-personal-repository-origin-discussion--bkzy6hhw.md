# Origin Discussion — Planning Studio and Central Personal Repository

## Nature of this record

This is a dated synthesis of the design discussion, not a verbatim chat
transcript. It preserves the ideas Robert explicitly asked to carry forward.
The individual supplied source files and submitted reviews remain separate.

## Ideas established in the discussion

- Planning Studio is a durable home for important early work that has moved
  beyond `_working/` but has not entered an approved roadmap.
- CoS is both a possible intake interface and an important reader of the
  repository; automatic CoS writes remain a later design question.
- The durable repository belongs to Robert, not to a specific agent, model,
  application, UI, or domain.
- Curator supplied the first real cross-domain case: personal curiosity can
  produce research, affect CoS continuity, and raise Guild planning questions
  without belonging exclusively to any one domain.
- Source background, successive versions, interpretations, reviews, and
  Robert's decisions must remain distinguishable and retrievable.
- A future mini-moi instance may be portable to another person while keeping
  reusable domain baselines separate from Robert's personal state.
- mini-moi should continue through use-earned 1.x versions. `2.0` is a horizon,
  not a current commitment.
- A professional reference deck may eventually explain a proven release, but
  commercial positioning is outside this design pass.

## Current disposition

Claude reviewed the initial package. Robert concurred with the direction and
asked for a consolidated v0.9 candidate to be reviewed again before anything
is implemented. Robert then made source-version visibility explicit: the
history from one version to the next must remain visible as source files, not
only as hashes, records, database rows, or Git history.

This capture creates no roadmap or implementation authority.
