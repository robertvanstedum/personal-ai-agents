# Use-Driven Versioning Note

**Version:** 0.1  
**Date:** 2026-09-02  
**Status:** Design principle under review

## Principle

mini-moi advances through demonstrated personal usefulness, not architectural
ambition.

The current release is 1.1. Future changes should remain incremental 1.x
releases until their combined effect produces a materially different system
that Robert actually uses and benefits from.

## Consequences

- "2.0" is a horizon, not a target release.
- This initiative does not reserve 1.2, 1.3, or any other release number.
- A database, graph, UI, or portable installer is not valuable merely because
  it was completed.
- Architecture claims require operating evidence.
- If the project is not useful after sustained real use, it may be reduced,
  paused, or archived without declaring 2.0.

## Possible evidence for an eventual major version

No checklist is approved, but a major version would likely require evidence
such as:

- the repository materially improves continuity or decision quality;
- CoS uses durable context successfully across real sessions;
- more than one domain participates without losing clear boundaries;
- backup and restore are demonstrated;
- a clean independent instance can be initialized without Robert's content;
- Robert continues using the system because it provides value.

## Presentation artifact

A clear reference deck should be part of an eventual major release definition.
It should explain the system that was actually proven. A speculative deck does
not create the release.
