File-first is sufficient for durability and portability. It is not sufficient for concurrent mutation. Spec the durable objects as files; spec intake as a single-writer transaction over those files (temp dir + atomic rename, lockfile, or a tiny append-only log). Do not introduce Postgres until a projection must answer a query files cannot (cross-series search at scale, permissions). That is later.2. Role separation.
Keep the five names as a responsibility legend, not as intake fields Robert must fill. Default: origin = Robert or named agent; steward = Robert; domains = multi-value hint, optional at capture. Planning Studio is the folder. Guild is a later door.3. Friction and minimum safe automation.
Minimum automation that makes capture habitual:Drop or “save this” into an intake inbox.  
System mints ULID, slug, checksum, filename, next series revision, supersedes if series is known.  
System writes frontmatter and leaves the source bytes untouched.  
If series is ambiguous, ask one question: “Continue X, or new series?”  
Stop.

Do not auto-classify domains, do not auto-write CoS memory, do not auto-promote.4. Source file + provenance.
Necessary, but provenance should live in frontmatter on an orientation record and on the source’s sibling metadata, not as a second essay. One human-visible series page listing revisions; each payload file immutable. If a .md source already has frontmatter, do not wrap it in another Markdown file unless the source is binary or must remain byte-identical (docx, PDF, ZIP). This brief arriving as .docx is exactly why byte-identical sources matter.5. Revision scheme.
Monotonic integer per series, plus ULID on every record.  Series revision: R1, R2, R3 — what a reviewer sees.  
ULID: global identity and time order.
Do not derive revision from timestamps alone (clock skew, two captures in one second). Do not use semantic versions as the repository counter.

6. Concurrency before multi-agent writes.
Must be specified before any second writer:One intake process per repository at a time (lockfile with timeout).  
Allocate ULID first; detect duplicate ULID/slug before publish.  
Write payload + metadata to a staging directory; validate; atomic move into the series folder; then refresh orientation.  
If orientation refresh fails, the series still contains the new source; rebuild orientation from files.  
Never rewrite a published source file.  
Collision on series revision: abort and ask, do not take max+1 after a stale read.  
Tombstone for exceptional delete; no silent unlink.
