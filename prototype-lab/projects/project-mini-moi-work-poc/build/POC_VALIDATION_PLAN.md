# Mini-moi Work proof-of-concept validation plan

**Status:** Ready for Robert's use-validation sequence  
**Decision owner:** Robert  
**Current phase:** `prove`  
**Production authority:** None

## What is being proved

The validation covers both experiment deliverables:

- **Capability:** Mini-moi can preserve sources, authorship, revisions,
  approvals, dispositions, and resumption without sending or acting.
- **Working method:** Robert and the assigned agents can move from intent to a
  reviewed result through durable artifacts and independent evidence.

## Gate 1 — Code baseline

- Confirm W0a is present on the selected baseline.
- Resolve PR `#201` only through Robert's reviewed-diff decision.
- Record the exact merged or rejected commit before testing.
- Do not treat a merge as authorization for Chief of Staff integration.

## Gate 2 — File-level acceptance

Robert names one local, private test folder and one non-sensitive file. A small
local driver must:

1. open or create a bounded Work item;
2. preserve the supplied file without changing its bytes;
3. create a draft or derived artifact with explicit agent authorship;
4. accept a Robert edit as Robert-authored without relabeling earlier text;
5. stop and resume from disk; and
6. produce a receipt identifying exactly what was saved.

Record commands, hashes, visible result, and any defect. Do not commit the test
file or private path.

## Gate 3 — Thin Chief of Staff entry point

Build only enough integration for Robert to give Chief of Staff a job
description and say, **“Start cover letter.”** Chief of Staff should:

1. create a Career Work item;
2. preserve the posting as external material;
3. use only explicitly authorized Career sources;
4. create and store a first draft with correct authorship;
5. show Robert where the durable result is; and
6. wait for Robert.

Submitting, emailing, messaging, scheduling, or contacting a recruiter remains
out of scope.

## Gate 4 — Real-use observation

For the first real letter, retain only private evidence needed to continue the
work. Add a sanitized experiment note covering:

- whether the opportunity was important or exploratory;
- whether the selected evidence was truthful and relevant;
- how many substantial revision rounds occurred;
- what Robert repeatedly had to correct;
- what carried forward successfully; and
- any privacy, provenance, recovery, or usability defect.

The revision count is descriptive evidence, not a performance target.

## Keep decision

Robert decides whether to keep, revise, pause, or discard each deliverable.

- Keeping the **capability** permits planning for a private CoS Work `v0.9`.
- Keeping the **working method** permits promoting its stable parts toward a
  reusable Guild practice and later Master Craftsman material.
- A `v1.0` follows only after the first deployed use produces and closes the
  necessary refinements.
